# RNF-001 — Seguridad

**Tipo**: Requisito No Funcional de Seguridad

## Descripción

El sistema debe cumplir con los controles de seguridad definidos en el OWASP Top 10 2021.

## Requisitos Específicos

**RNF-001.1** — Las contraseñas deben hashearse con bcrypt (factor de costo mínimo 12) antes de persistirse.

**RNF-001.2** — Los tokens JWT deben firmarse con secretos de mínimo 32 caracteres aleatorios.

**RNF-001.3** — Los endpoints de autenticación deben tener rate limiting (máx. 10 req/15 min por IP).

**RNF-001.4** — La API debe usar HTTPS en producción (TLS 1.2+).

**RNF-001.5** — Las cabeceras HTTP de seguridad deben configurarse con `helmet` (CSP, HSTS, X-Frame-Options).

**RNF-001.6** — El CORS debe configurar orígenes explícitos — nunca `origin: "*"` en producción.

**RNF-001.7** — Toda consulta a la BD debe usar Prisma ORM (no SQL crudo con interpolación de strings).

**RNF-001.8** — Los siguientes eventos de seguridad deben registrarse en el log de auditoría con formato JSON estructurado (OWASP A09 — Security Logging and Monitoring Failures):
  - `LOGIN_SUCCESS` — login exitoso (con `userId` e IP)
  - `LOGIN_FAILED` — login fallido (con motivo, sin email completo)
  - `PASSWORD_CHANGED` — cambio de contraseña exitoso (con `userId`)
  - `PASSWORD_RESET_REQUESTED` — solicitud de recuperación de contraseña
  - `EMAIL_VERIFIED` — verificación de email exitosa (con `userId`)
  - `RATE_LIMIT_HIT` — límite de velocidad alcanzado (con endpoint e IP)

# RNF-002 — Rendimiento

**Tipo**: Requisito No Funcional de Rendimiento

## Requisitos Específicos

**RNF-002.1** — El endpoint de login debe responder en menos de 500ms en condiciones normales (incluyendo verificación bcrypt).

**RNF-002.2** — El pool de conexiones PostgreSQL debe configurarse con mínimo 2 y máximo 10 conexiones.

**RNF-002.3** — El frontend debe cargar el bundle inicial en menos de 3 segundos en una conexión de 10 Mbps.

# RNF-003 — Mantenibilidad

**Tipo**: Requisito No Funcional de Mantenibilidad

## Requisitos Específicos

**RNF-003.1** — La cobertura de tests debe ser mínimo 80% en módulos de lógica de negocio.

**RNF-003.2** — El código debe pasar ESLint sin errores antes de cada commit.

**RNF-003.3** — Todos los tipos TypeScript deben ser explícitos — no usar `any` sin justificación documentada.

**RNF-003.4** — Cada archivo debe tener cabecera de documentación (¿Qué? ¿Para qué? ¿Impacto?).

---

# RNF-004 — Usabilidad y Accesibilidad

**Tipo**: Requisito No Funcional de Usabilidad

## Requisitos Específicos

**RNF-004.1** — La interfaz debe soportar dark mode y light mode con toggle visible.

**RNF-004.2** — El contraste de color debe cumplir WCAG 2.1 AA (mínimo 4.5:1 para texto normal).

**RNF-004.3** — Todos los formularios deben ser operables completamente con teclado.

**RNF-004.4** — Los mensajes de error deben anunciarse con `role="alert"` para lectores de pantalla.

**RNF-004.5** — El diseño debe ser responsive — funcionar correctamente en viewport de 320px a 1920px.

# RNF-005 — Internacionalización (i18n)

**Tipo**: Requisito No Funcional de Internacionalización

## Descripción

El sistema debe soportar múltiples idiomas en la interfaz de usuario, comenzando por Español e Inglés.

## Requisitos Específicos

**RNF-005.1** — Los idiomas soportados son exclusivamente: `"es"` (Español) y `"en"` (English).

**RNF-005.2** — El idioma predeterminado del sistema es `"es"` (Español).

**RNF-005.3** — El idioma seleccionado por el usuario debe persistirse en `localStorage` (`i18nextLng`) para cualquier usuario (autenticado o no).

**RNF-005.4** — Para usuarios autenticados, la base de datos es la fuente de verdad del idioma: el campo `locale` en la tabla `users` se actualiza vía `PATCH /api/v1/users/me/locale`.

**RNF-005.5** — Al iniciar sesión, el idioma del perfil del usuario (campo `locale` en la respuesta de login) sobreescribe el valor de `localStorage`.

**RNF-005.6** — El campo `locale` devuelto en `GET /api/v1/users/me` y `POST /api/v1/auth/login` debe ser siempre uno de los valores soportados: `"es"` o `"en"`.

**RNF-005.7** — El servidor debe validar y rechazar (HTTP 422) cualquier valor de `locale` que no sea `"es"` o `"en"`.
